# Repository organization

The biggest problem in this repository is not Docusaurus itself. The problem is that exported working notes, duplicate pages, and large field media were committed directly into the published docs tree without a stable structure.

That creates three kinds of pressure:

1. **Navigation pressure**: autogenerated sidebars expose raw export folders, UUIDs, placeholder pages, and duplicate content.
2. **Build pressure**: Docusaurus has to scan and process a very large docs tree before it can publish the site.
3. **Server pressure**: large images and videos are shipped as site assets when they are referenced by published docs.

## Directory rules

Use these top-level sections for published documentation:

- `docs/00-Problem/` - problem statements and mission context
- `docs/charging-station/` - charging-station product work, cases, tasks, and notes
- `docs/01-outsourcing-engineering/` - outsourced engineering/product experiments
- `docs/team/` - team and lab information
- `docs/communication/` - outreach, partners, and public communication
- `docs/reports/` - progress reports and status summaries
- `docs/maintainers/` - repository maintenance docs

Keep raw exports, experiments, and temporary dumps out of published docs. Move them to an archive that is not included in the Docusaurus sidebar, or mark unfinished pages as drafts until they are cleaned.

## Naming rules

For new docs and folders:

- Use lowercase kebab-case filenames: `power-core.md`, not `Power Core.md`.
- Avoid spaces, trailing spaces, parentheses, and UUID-only folders.
- Prefer `index.md` or `readme.md` for section landing pages.
- Add front matter when a page needs a stable route:

```md
---
slug: /charging-station/power-core
sidebar_position: 2
---
```

## Media rules

Use media intentionally:

- Do not commit original phone-camera dumps directly into `docs/`.
- Resize documentation images before publishing. A maximum edge of 1600 px is enough for most docs pages.
- Prefer compressed JPG/WebP for photos and PNG only for screenshots or diagrams that need sharp text.
- Store videos outside the docs site when possible and link to them. If a video must be committed, keep it short and optimized.
- Run `npm run optimize:media` before committing batches of images.

Large binary files should use Git LFS so future commits do not keep expanding the repository history.

## Current known cleanup targets

- Deduplicate repeated case pages and their media.
- Replace raw export folder names with readable categories.
- Move unreferenced raw media out of the published docs tree.
- Decide a canonical location for charging-station case media.
- Keep `npm run build` passing before publishing.
